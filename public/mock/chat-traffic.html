Map Lab / Proposal

通信線 ChatTraffic モック

大陸間の通信線を描く実装は存在しますが、描画呼び出しだけが接続されていません。 左が現在の見え方、右が「いつ・どこへ・どれだけ情報が届いたか」を可視化する改善案です。 2つの地図は同じ時刻・同じ計算結果で同期しています。

経過M00
同時通信0
到達都市0
延べ影響人口0M
左も右も同じ計算。違いは描画の有無だけです。

改善案のポイント

既存のロジックを壊さず、見え方と操作だけを足す

01 / CONNECT

描画を接続する

合成パスの直後に chatTraffic.draw(view, elapsed) を1行追加。計算済みの通信帯がそのまま表示されます。

02 / MEANING

情報の意味を持たせる

線は「発信拠点 → 到達都市」。到達点はパルスで示し、太さは影響人口、色は自律利用と依存で分けます。

03 / CONTROL

量を絞る

同時2本、寿命は約1か月、重要度の上位だけ。既存の MAX_TRANSMISSIONS と MIN_IMPACT_POPULATION を維持します。

04 / LEGIBILITY

凡例と操作を付ける

地図の凡例に通信線を追加し、ON/OFF とホバー詳細を用意。色だけに頼らず、ラベルでも到達先を読めるようにします。

05 / COST

非表示時は計算も止める

現在は見えないのに beginExpansion が毎月走っています。OFF 時は更新自体をスキップし、表示時も最大2本に制限します。

実装チェックリスト

見た目だけで終わらせないための確認項目

  • draw() が毎フレーム呼ばれ、通信が0本のときは即 return する
  • 通信線 OFF で beginExpansion も止まる
  • 4倍速でも到着と消滅が判別できる
  • 日付変更線をまたぐ経路が二重に出ない
  • リサイズ・DPR変更後も線と都市がずれない
  • 凡例・ホバー・読み上げで色以外の手掛かりがある
  • prefers-reduced-motion でパルスが止まる
  • スクリーンショットで現状との差分を確認した
