# 海面描画の調査（2026-10-28）

## 現在の実装

`src/components/OceanSurface.tsx` が背景地図の上に透明なWebGL Canvasを重ねる。`src/map/oceanShader.ts` で4本の正弦波を足し合わせ、中央差分で傾きを計算し、法線と固定光源から反射を求める。2本には低周波の位相変調があるが、基本は一定方向へ進む周期波である。背景をサンプリングした屈折や、環境の映り込みはない。

白または黒の透明色を最大0.006（0.6%）で合成する。`src/game/data/map/ocean-surface.json` の設定は時間係数0.18、CSS寸法の75%解像度、最大30fps、ゲーム速度の反映は最大2倍。一時停止中は動かない。海岸からの距離マスクで陸と海岸近くを除外する。地図は高さに合わせて縮尺が決まるため、スマホの縦横の向きでも波の画面上の密度が変わる。

## 斜線に見える理由

以下はコードからの推定であり、スマホ実機による確認結果ではない。

- 長く連続する正弦波の等位相線が斜めの縞になる。振幅だけでなく傾きへの寄与は周波数にも比例するため、高周波成分の細い筋が目立ちやすい。位相の小さな変調だけでは筋の連続性を十分に崩せない。
- 固定した光に対する反射差を白黒に変換するだけなので、水が局所的に盛り上がり、反射が生まれて消える手掛かりが少ない。光沢の変化が周期模様の移動として読まれやすい。
- 1倍速で主成分の1周期は約35秒、他の成分は約48〜90秒。短時間の観察では動きが分かりにくい。開始直後の一時停止状態では完全に静止する。
- 最大0.6%のアルファは8ビット換算で約1.53段階しかない。暗い背景では白い筋だけが認識され、黒い変化がほぼ見えない可能性がある。単純な強度増加は縞も強める。
- `devicePixelRatio` を使わずCSS寸法の0.75倍で描く。DPR 3の端末では物理画素に対して縦横それぞれ約1/4の解像度になる。拡大補間で細かな変化が失われる可能性がある。単に解像度を上げても周期的な縞自体は解決しない。

別の問題として、`preserveDrawingBuffer: true` なのに描画前の `gl.clear` がなく、陸や表示領域外を `discard` している。横移動時に、以前の海の画素が新しい陸や余白へ残る条件がある。「消えない」が残像を指す場合はこの経路を確認する必要がある。これは波形とは別の修正項目になる。

## 推奨する改善

この世界地図では、波の山を実寸で見せるより、細かな反射が不規則に変化する穏やかな演出を目標にする。まず既存の透明Canvasと海岸マスクを使い続け、次の順番で試作する。

1. 毎回透明色で描画領域をクリアし、横移動時の残像を除く。
2. 大きなうねりと細かいさざ波の2層に分けた法線を作る。異なる方向・速度の周期ノイズまたは法線テクスチャを重ね、弱い座標変調と振幅変調で長い直線を分断する。経度方向の継ぎ目は周期を保つ。ノイズをそのまま明暗にすると雲状になるため、法線と反射の計算に使う。
3. 法線から広い弱い反射と局所的なハイライトを計算する。筋を全面へ均等に出すのでなく、小さな反射が生まれて消えるよう調整する。速度・粗さ・強度を独立した設定にし、短い動画で揺らぎが読める値を選ぶ。値は実機比較後に決定する。
4. DPRと描画画素数の上限を明示して解像度を決める。波の最小波長も描画画素数に合わせ、解像度以下の成分を弱めてちらつきを防ぐ。全DPRの無制限利用は避け、スマホのフレーム時間を測る。
5. 背景の歪みが必要なら、海の色だけを別テクスチャとして読み、法線に応じて微小にUVをずらす。海岸・陸・国境まで歪まないようサンプル先にもマスクを適用する。これは反射の改善後に判断する。

最初の試作ではFFT海洋シミュレーションや3Dメッシュの導入は不要。Gerstner波は波頭や水平変位を見せる斜め視点で検討する方式で、この俯瞰地図ではまず法線と反射の改善を優先する。方式の自動切り替えは追加しない。

## Web上の実装例を比較した結論

追加調査では、単に正弦波をノイズへ置き換えるだけでなく、「方向性を保った細かな波」と「場所ごとに変化する反射」を組み合わせる方針に絞った。以下は資料に基づく設計判断であり、このプロジェクトで画質・速度を実測した結果ではない。

| 方法 | 資料の要点 | この地図への適用判断 |
| --- | --- | --- |
| 異なる速度・方向の法線マップを合成 | Alex Tardifの実装は2枚の法線と、反射を分断するノイズを使用 | まず採用する構成。滑っていく縞ではなく、干渉で変化する小さな光沢を作る |
| フローマップによる局所的な変形 | Catlike Codingは場所ごとの流速を使い、位相をずらした描画の合成で変形のリセットを隠す | 低周波の弱い変形として追加。全画面で同じ方向へ流れる印象を減らす |
| 方向を持ったさざ波 | Catlike CodingのDirectional Flowは、等方的なノイズの歪みだけでは穏やかな波の向きが不適切になる点を指摘 | 無方向なノイズだけにしない。短く曲がった波の連なりに、緩やかな主方向を残す |
| 波の構成自体を時間変化 | NVIDIAは波をフェードアウトし、別のパラメータで入れ替える方式を説明 | 大きなうねりを残す場合に使う。一定の4本を永久に流し続ける構成は避ける |

推奨する最小構成は、短い波形を持つシームレスな法線を2層、異なる縮尺・方向・速度で合成し、弱い局所的な座標変形を加える方式。その法線から反射を計算し、連続的に動くノイズでハイライトの強さを変調する。ノイズを白黒模様として直接表示したり、毎フレーム乱数で点滅させたりはしない。海岸マスク・地図座標・経度方向の接続を維持する。

「規則性をなくす」は完全な無方向化ではない。風に沿う大まかな方向を残しながら、波の長さ・局所方向・強度・位相を分散させる。画面全体を横切る等間隔の筋と、固定パターン全体の平行移動が見えないことを優先する。

## 検証方法と限界

既存の `tests/browser/ocean.spec.ts` は陸の1点の透明度、時間進行による画像の変化、停止時の静止を確認する。水らしさ、スマホの見やすさ、横移動後の残像を保証するテストではない。

改善時はPCとスマホ縦横で、同じ海域・同じ時刻の10秒程度の動画を比較する。一時停止と1倍速を区別し、直線の連続性、反射の生成と消失、海岸の固定、日付変更線の接続、ドラッグ後の残像、フレーム時間を確認する。DPR 1/2/3で描画寸法も記録する。エミュレーションに加えてiOS SafariとAndroid Chromeの実機確認が必要。
